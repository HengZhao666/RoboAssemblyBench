# 仿真修复闭环

## 只加载当前任务需要的内容

先读项目短总入口、用户所选路线交接及检查。路线不明且影响操作时先澄清，可继续独立整理。分清只分析、文档整理、离线修改与正式仿真；交接和本技能不提供运行授权。

不默认读取另一条路线、混合历史、整个证据索引或旧会话。路线事实、计数、成功门和版本不得互用。只迁移下面的方法；确需借用具体实现时另列适用条件并在当前路线验证。

## 一轮的最小闭环

一轮是一组可独立核验的修复包和一次正式验收，不是只修一个问题。已定位、互不冲突的问题可同时修复并分别核验；仅为区分强耦合未知物理机制才拆分对照，不强迫每项各跑长仿真。

1. **锚定问题**：核权威源码、配置、回退与授权，先读相关生产代码和真实失败窗口。把本轮发现集中到已有差异记录的短清单：问题/证据、修复及可证伪条件、已修复/已知缺测/需实验；冻结前扫查同族调用点，避免只补首个报错。
2. **先便宜后昂贵**：用实际配置走真实worker build→框架名称映射→生产预检入口的无物理冒烟，先抓接口/名称/配置错误；不能用单函数测试冒充整条构建链。再以真实危险反例、能推进的正例和单位成本验证受影响的控制边/缓存/实体路径，按差异选择检查。缺现成冒烟入口须说明实际覆盖，不称已经实现。
3. **验证执行链**：区分请求、最终发布、SDK接受、实际执行和反馈；使用真实连续context、非零跟踪偏差和演化状态。完整双方机械臂、夹爪、持件及相关环境不能省略；扫掠与复用按 [review-and-reuse.md](references/review-and-reuse.md) 执行。
4. **一次正式验收**：启动前给出必需检查范围与短预算；超出时说明具体阻塞、剩余动作和预计耗时。流程整理、非依赖文档和重复检查不得挡已授权启动，确有未通过的必需安全检查除外。运行只在当前授权内，确认第一动作/证据增长，保留首次失败和规定尾段，不改成功门。
5. **一次后审收尾**：复用固定入口和原件索引；按同物理时刻核三视图、最终目标、实际状态与接触，保留原报告错误/跳过/缺测。终态raw缺帧是可与其他无冲突修复合并的采集缺陷，核终止/采样顺序，不能放宽门或回填旧false。结论进最小机器记录/短交接，文档一次批量同步。

完整装配、局部阶段、配置检查、离线回放和视频外观是不同证据。检查数和运行步数不作为装配进展。

## 经验转成可复用实现

共性缺陷按零件、阶段和控制边枚举调用点；在同一问题清单记录适用条件、共用入口、旧失败反例和推进正例，各点标已验证/相容复用/未覆盖。修复一处不代表其他调用点已受保护，不另建同义台账或回填通过。

能共享的机制在原共用模块实现；路径和数值按各自实际几何、抓取关系及另一臂状态生成并分别验证，不能复制单件参数。保留可重放的旧失败输入，使以后相关修改能直接重验；无需为未变领域重复完整运行。通用方法进本技能，项目检查/路线机制及实验事实各归原处。

## 局部修改默认差异审查

已有合格基线且修复包差异可枚举时，默认轻量审查。沿用同一记录绑定基线/候选身份、精确差异、复用适用域和重验结果；公共模块/物理合同变化、输入超域或新故障只扩大相关依赖，不自动重跑全仓库或新增审批。

- 启动前重验受影响模块、相邻控制边和保护不变量，宽回归复用封存基线。变化路径须核最终限幅后的完整双方几何扫掠；未改阶段按输入域复用。候选冻结后核整源身份一次；同源不因网络重连重跑，身份核对不等于全套测试。
- 每次新运行仍采集原始执行链、三视图、首次失败和规定尾段；固定机器后审运行一次，异常/缺测原样保留。人工详审聚焦改动段、相邻切换、首失败和回归异常；未改前段只核本轮回归摘要，沿用旧分析方法，不把旧运行结果写成本轮实测。
- 三路原片保留并核SHA，完整解码一次、本机只做兼容性抽检。先核片段索引，只制改动段、失败/尾段和必要锚点，仅重建失效片段。复用已有检查/打包/同步入口，不为每轮另造脚本、报告或重复预览。
- 固定偏差或理想响应的回放不能支持受载瞬态修复。连续两次无实质进展即停同类局部试错，先取得能区分原因的针对性证据，再决定候选；不靠不断调一个参数消耗完整运行。具体运行授权仍由当前人类指令和路线账本决定。

## 中段排查与断点复用

只改后续阶段时，先用已有真实中段输入离线回放。断点保存、恢复和清理是否已实现、已验证、已授权，只读所选路线交接；方法被采纳不等于运行授权。

1. **少量稳定节点**：选安装/释放/退避后对象与约束稳定的边界，避开接触切换，不逐步存档。保存双臂/夹爪q与速度、驱动/最终目标、零件位姿/速度、约束/冻结抓取关系、控制缓存/积分、阶段/计时/稳定计数、随机状态、物理/相机时钟及源/工具/资产/配置/物理参数身份。求解器/接触内部状态等缺口明列；仅恢复q/位姿或阶段号不算完整恢复。
2. **先验证恢复**：同一未改代码/配置对比连续运行与恢复，用同钟native、发布/SDK、三视图和接触核误差、推进及原成功门，保留首次分歧，不放宽门或先称等价。实测保存/恢复/校验成本和省下的前段墙钟再判断收益。
3. **按依赖复用**：限于后段修复且前段依赖兼容，绑定原身份、差异和输入域；全源SHA变化或阶段同名均不能单独决定兼容。公共控制、资产、配置、物理参数或前段变化时，重验受影响前段并使相关断点失效。
4. **验证后替换/清理**：每节点留最新已验版和一个回退；新保存并恢复验证后才替换。核范围/引用/保护，只删失效、被替代且无引用的断点；保留有用基线、原日志/视频/失败与源码封存。

中段搭场景或恢复只证明相应后段；完整成功仍需按项目合同从头验收。初始化写入状态与正式路线“不改位姿/速度”的边界冲突时，只能留在明确隔离、标注的局部调试入口，不暗改正式路线。未实现/未验证项直说。

## 简短反馈

用户未要求时，不额外写报告、汇报文档或分析图表。默认用最简单的话说清“问题在哪、可能根因是什么、当前结果/下一步”；保留必要原始证据、机器校验和短交接。根因未被动态对照证实时用“可能/支持”，不写成确定因果。

## 何时复盘流程

采用项目规定的频率；没有规定时每两次正式尝试简短复盘。新瓶颈、阶段切换、跨模块、重复工程错误或两轮无实质改善提前触发。广审依赖链，不等于重跑所有长检查。按 [process-retrospective.md](references/process-retrospective.md) 决定哪些规则值得保留。

## 维护与交接

版本身份以源/工具/配置清单SHA为准，Git提交只是其中一项。文档版本、技能版本、控制源码版本及运行编号分开；保留旧清单、原件与回退，目录名不充当身份。

每轮只改所选路线的当前交接/账本/发现。共用方法改变才更新技能、项目流程和共用检查；只修改适用条目，替换旧规则，避免追加同义规则。项目约束或新增方法需要确认时遵循现有授权，不把已批准整理误作暂停恢复。

日常交接保留状态/权限、权威路径、封存/回退、短问题清单、下一验收及证据/媒体/同步入口；历史按需检索。状态只维护一处，其余引用。文档同步可用 [sync_documents.py](scripts/sync_documents.py) 按显式清单一次打包逐SHA核验；它不启动仿真或部署控制源码。
